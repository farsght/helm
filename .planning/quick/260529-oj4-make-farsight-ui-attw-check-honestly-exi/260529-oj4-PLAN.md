<objective>
Make @farsight/ui pass @arethetypeswrong/cli honestly for its intentionally ESM-only / bundler-profile design, and wire the check as a supported npm script.

Purpose: The attw exit 1 recorded in 04-VERIFICATION.md (Deviation 1 / PORT-02 limitation) was a known deferred item. The root cause is fully diagnosed: `attw --pack` shells out to `npm pack`, which does NOT apply `publishConfig.exports`, so attw resolves types from `src/index.ts` (dev exports) with extensionless relative imports — producing 150 spurious `InternalResolutionError` against files that are not in the published tarball. The real `dist/index.d.ts` uses correct `.js` extensions and is fine. Separately, `pnpm pack` does apply `publishConfig.exports` but crashed attw 0.18.2 (exit 3) because the published set was unrestricted (tests/config included). This plan fixes both root causes.

Two coordinated edits to packages/ui/package.json:

**1. Add `files` allowlist.**

The current package.json has no `files` field. Add it so that `pnpm pack` (and npm publish) includes only the publishable artifacts, excluding tests, config files, and the source tree. This de-crashes attw 0.18.2, which exited 3 ("Cannot read properties of undefined (reading 'filename')") on an unrestricted tarball containing vendored dist/node_modules + tests.

Allowlist to add (place after the `"sideEffects"` field):

```
"files": [
  "dist",
  "src/styles",
  "README.md",
  "CONSUMER.md"
]
```

The `src/styles` entry is needed because `publishConfig.exports` maps `./theme.css` and `./styles/globals.css` to `./dist/styles/theme.css` / `./dist/styles/globals.css` — those are already in `dist/styles/`. However the `files` allowlist also covers the case where some tools read the non-publish exports (dev workspace consumption). Including `src/styles` costs nothing (plain CSS) and prevents a "file not found" edge case on the dev export side. Do NOT include `src/index.ts` or any TypeScript source — the published artifact is dist-only.

**2. Add `check:attw` script.**

The script must:
- Build the package first (`npm run build`) so `dist/` is fresh.
- Pack with `pnpm pack --pack-destination /tmp` to produce a `.tgz` where `publishConfig.exports` IS applied (pnpm applies it; npm pack does not).
- Run attw against the tarball with `--profile esm-only` (targets only the bundler profile, which is the consumer that matters per project constraint) and `--exclude-entrypoints theme.css styles/globals.css` (these CSS subpaths have no `.d.ts` — they are legitimately untyped; excluding them is honest, not masking).
- Clean up the tarball after.
- MUST NOT pass `--ignore-rules internal-resolution-error` or any other rule-suppression flag. If a real InternalResolutionError exists against dist, the check must surface it.

The script shell is bash-compatible (runs in the packages/ui directory). Capture the tarball name from `pnpm pack` output. A workable invocation pattern:

```
"check:attw": "npm run build && TARBALL=$(pnpm pack --pack-destination /tmp 2>&1 | grep '.tgz' | tail -1 | tr -d '[:space:]') && npx @arethetypeswrong/cli $TARBALL --profile esm-only --exclude-entrypoints theme.css styles/globals.css; STATUS=$?; rm -f $TARBALL; exit $STATUS"
```

### attw Scope

`check:attw` validates `@farsight/ui` for its intentional design:

- **Validated:** `--profile esm-only` — the bundler profile, which is the only profile
  Farsight's Vite/`apps/web` consumer will use. The `.` entry must be 🟢.
- **Excluded entrypoints:** `theme.css` and `styles/globals.css` — these are CSS assets
  with no `.d.ts` counterpart. attw cannot resolve CSS entries; excluding them is correct
  and honest (not masking a real type problem).
- **Out of attw scope (by design):**
  - `node10` / `node16-CJS` profiles — the library is deliberately ESM-only
    (`type: "module"`, `moduleResolution: "bundler"`, `platform: "browser"`). CJS output
    is not a project requirement.
  - `./theme.css` / `./styles/globals.css` subpath entries — CSS exports have no associated
    type declarations; they are excluded via `--exclude-entrypoints`.

The check uses `pnpm pack` (not `npm pack`) so that `publishConfig.exports` is applied —
the tarball attw reads contains the real `dist/index.d.ts`, not the dev `src/index.ts`.
Passing `--ignore-rules internal-resolution-error` is explicitly NOT used; any real
dist-level type resolution error will surface as a failure.
```
