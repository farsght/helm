<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→FarsightProvider | Clerk Bearer token flows from Clerk's getToken() into SDK; never logged or persisted |
| FarsightProvider→QueryClient | QueryCache/MutationCache onError intercepts auth.*/rbac.* before surface code sees them |
| consumer→FarsightProvider | onError prop is consumer-supplied callback; provider never leaks internals beyond code + message |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Information Disclosure | Clerk Bearer token in SDK client | mitigate | getToken() called per-request inside SDK; token is never stored in React state, context, or QueryClient cache; only passed as a callback reference. Log nothing in the provider. |
| T-03-03 | Information Disclosure | Cross-tenant cache bleed on org switch | mitigate | Per D-03: query keys namespaced by orgSlug/projectSlug (defense-in-depth); documented key={orgSlug:projectSlug} remount contract for consumer. multi-org-cache.test.tsx verifies cache isolation. |
| T-03-04 | Information Disclosure | RFC-7807 error details surfaced to UI | mitigate | Per D-09/D-10: provider onError receives (error, code) — code only, no internal details; per-form validation.* details surfaced only in form field context; message is human-readable only. Never branch on message text. |
| T-03-05 | Spoofing | JWT token replay after org switch | accept | Clerk rotates JWTs on setActive(); SDK calls getToken() per request, so stale tokens are not replayed. Provider's responsibility ends at wiring getToken. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new external npm packages in this plan. All files are local source. |
</threat_model>
