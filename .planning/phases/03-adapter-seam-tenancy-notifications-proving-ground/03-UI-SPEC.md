# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: Adapter Seam, Tenancy & Notifications Proving Ground.
> Surfaces in scope: NotificationBell, NotificationInbox, NotificationPreferences, WebhookList, WebhookCreateModal, WebhookRotateSecretModal, WebhookSecretReveal, WebhookHealthBadge.
> All design tokens resolve from Phase-1 `src/styles/theme.css`. No new palette. No new typography scale.

## Spacing Scale

Declared values (all multiples of 4 — 8-point base grid):

| Token | Tailwind | px | Usage in Phase 3 |
|-------|----------|----|------------------|
| xs | `gap-1` / `p-1` | 4px | Icon-to-text gap inside notification items; badge inner padding |
| sm | `gap-2` / `p-2` | 8px | Compact row padding (preference rows, webhook row cells) |
| md | `gap-4` / `p-4` | 16px | Default card body padding; notification item inner padding |
| lg | `gap-6` / `p-6` | 24px | Section padding inside modals; panel padding |
| xl | `gap-8` / `p-8` | 32px | Top-level surface padding (NotificationInbox page wrapper) |
| 2xl | 48px | — | Not used in Phase 3 surfaces |
| 3xl | 64px | — | Not used in Phase 3 surfaces |

**Exceptions:**

- **Touch targets:** Icon-only buttons (NotificationBell button, copy-to-clipboard button, webhook enable-toggle) must be minimum `h-9 w-9` (36px) on mobile, `h-8 w-8` (32px) on desktop — Radix primitives size these correctly with `size="sm"` Button variant. The copy button inside the secret-reveal modal uses `h-8 w-8 p-0`.
- **Popover max-width:** NotificationBell popover is `w-80` (320px) max, not tied to the spacing scale — a layout constraint, not a spacing token.
- **Webhook list row:** Use `py-3 px-4` (12px / 16px) for table rows to match Phase-2 ListSkeleton's `px-4 py-3` baseline.

## Typography

Reuses the Phase-1/2 type scale exactly. No new sizes introduced.

| Role | Tailwind | Size | Weight | Line Height | Usage in Phase 3 |
|------|----------|------|--------|-------------|------------------|
| Body | `text-sm` | 14px | 400 (normal) | 1.5 | Notification body text, webhook URL, preference labels |
| Label / Meta | `text-xs` | 12px | 400 (normal) | 1.4 | Category badge, timestamp, `signingSecretPrefix`, event-type chips |
| Heading | `text-base font-medium` | 16px | 500 (medium) | 1.25 | Notification item title, modal title, preference section heading, panel heading |
| Display | `text-lg font-medium` | 18px | 500 (medium) | 1.2 | NotificationInbox page heading (via shadcn Card or inline `<h2>`) |

**Weight contract:** Two weights only.
- Regular (400): all body copy, meta, timestamps, URLs, helper text.
- Medium (500): headings, titles, action labels, column headers.

No `font-bold` (700) or `font-semibold` (600) on Phase 3 surfaces — those are reserved for page-level headers (PageHeader, metric values) which are not in scope here.

**Unread indicator typography:** Unread notification items render the title at `font-medium` (500). Read items render at `font-normal` (400). This is the sole weight-based read/unread distinction — no italic, no underline.

## Color

All values are CSS custom property references from `src/styles/theme.css`. No hardcoded hex anywhere in Phase 3 components. All severity colors MUST be sourced from `tokens.ts` or the `tokens.color.*` extension below.

| Role | Token / Tailwind | Light value (approx) | Dark value (approx) | Usage |
|------|-----------------|----------------------|----------------------|-------|
| Dominant surface (60%) | `bg-background` / `--color-background` | white | near-black | Page surfaces, popover backgrounds |
| Secondary surface (30%) | `bg-card` / `--color-card` | white | dark gray | NotificationInbox card, WebhookList card, preference panel |
| Accent (10%) | `text-primary` / `--color-primary` | green `oklch(0.723 0.219 149.579)` | same | Primary CTA buttons; "Mark all read" link text |
| Destructive | `text-destructive` / `--color-destructive` | red `oklch(0.577 0.245 27.325)` | adjusted | `severity: error` icon; delete ConfirmDialog confirm button; error ErrorState icon |

**Accent reserved for:** Primary action buttons (create webhook, save preferences), "Mark all read" text-link action, unread count badge background, active/checked Switch thumb. Do NOT use `text-primary` for general body text, timestamps, or metadata.

**Severity color contract — notification items and health badges:**

These four mappings are the ONLY places severity/status colors appear. All reference `tokens.ts` (extended) or existing tokens — zero hardcoded hex.

| Severity / Status | Token | Tailwind class | Source | Lucide icon |
|-------------------|-------|----------------|--------|-------------|
| `error` | `tokens.color.destructive` | `text-destructive` | Phase-1 `tokens.ts` — existing | `XCircle` |
| `warning` | `tokens.color.warning` | `text-[var(--color-chart-4)]` | **Add to `tokens.ts`** as `warning: 'var(--color-chart-4)'` — resolves to amber `oklch(0.828 0.189 84.429)` light / `oklch(0.627 0.265 303.9)` dark | `AlertTriangle` |
| `success` | `tokens.color.primary` | `text-primary` | Phase-1 `tokens.ts` — existing | `CheckCircle2` |
| `info` | `tokens.color.mutedFg` | `text-muted-foreground` | Phase-1 `tokens.ts` — existing | `Info` |
| `null` (no severity) | `tokens.color.mutedFg` | `text-muted-foreground` | fallback | `Bell` |

**tokens.ts extension required (Executor task):** Add `warning: 'var(--color-chart-4)'` to the `tokens.color` object. No new CSS variable is needed — `--color-chart-4` already exists in theme.css and maps to `var(--chart-4)`.

**Health badge color contract — webhooks:**

| Derived status | Tailwind | Visual |
|----------------|----------|--------|
| `Healthy` | `text-primary bg-primary/10` | Green — Badge variant="outline" + custom className |
| `Failing` | `text-destructive bg-destructive/10` | Red — Badge variant="outline" + custom className |
| `Disabled` | `text-muted-foreground bg-muted` | Gray — Badge variant="secondary" |

Use shadcn `<Badge>` with `variant="outline"` + inline className override for Healthy/Failing. Use `variant="secondary"` for Disabled. Do NOT use Badge `variant="default"` (that is primary green — reserved for the accent role).

**Unread notification indicator:** Unread items render a solid `h-2 w-2 rounded-full bg-primary` dot as the visual unread mark, positioned at `flex-shrink-0` before the severity icon. Read items render no dot.

**NotificationBell badge:** The unread count badge uses `bg-destructive text-white text-xs` positioned `absolute -top-1 -right-1` on the bell button. When `unreadCount === 0`, the badge is hidden (`hidden`). When `unreadCount > 9`, display "9+" (cap at single digit).

**Muted / locked state (preference panel — security row):** The security toggle row renders with `opacity-50 cursor-not-allowed` and the Switch `disabled` prop set to `true`. A `Lock` (lucide) icon appears at `text-muted-foreground` next to the label. The row background is unchanged (no special bg-muted fill).

## Surface Specifications

### 1. NotificationBell

**Form factor:** Icon button with badge overlay, renders a Popover on click.

**Anatomy:**
- Trigger: `<Button variant="ghost" size="icon" aria-label="Notifications">` wrapping `<Bell className="h-5 w-5" />`
- Badge overlay: `absolute -top-1 -right-1 h-4 w-4 rounded-full bg-destructive text-white text-[10px] font-medium flex items-center justify-center` — shows `unreadCount` when >0, "9+" when >9
- Popover content: `w-80 p-0` — header row ("Notifications" label + "Mark all read" text button) + scrollable list via `<ScrollArea className="max-h-96">` + individual `<NotificationItem>` rows
- "Mark all read" is a `<Button variant="ghost" size="sm" className="text-primary text-xs">` — only shown when `unreadCount > 0`
- Live region: wrap the badge in `<span aria-live="polite" aria-atomic="true">` so screen readers announce count changes

**States:**
- Loading: show 3 `<NotificationItem>` skeleton rows (inline skeleton, not full ListSkeleton)
- Empty (0 notifications): `<EmptyState title="No notifications" icon={Bell} />` inside the popover
- Error: `<ErrorState title="Could not load notifications" onRetry={refetch} />` inside the popover
- Data: list of `<NotificationItem>` newest-first

**Keyboard:** Popover trigger must be focusable (Button). Popover closes on Escape. Items in list are focusable with Tab. "Mark all read" is focusable.

**Form factor:** Full-width list with header row + paginated item list.

**Anatomy:**
- Page wrapper: `<div className="p-8">` (xl spacing)
- Heading row: `<div className="flex items-center justify-between mb-6">` — `<h2 className="text-lg font-medium">Notifications</h2>` + "Mark all read" `<Button variant="outline" size="sm">` (shown only when `unreadCount > 0`)

### 3. NotificationItem (shared row, used in both Bell popover + Inbox)

**Anatomy (single row):**
```
[unread-dot?] [severity-icon] [content] [timestamp]
```
- Unread dot: `h-2 w-2 rounded-full bg-primary flex-shrink-0` — only when `readAt === null`
- Severity icon: Lucide icon component at `h-4 w-4 flex-shrink-0`, colored via severity token (see Color section)
- Content block: `<div className="flex-1 min-w-0">`
  - Title: `<p className="text-sm font-medium truncate">` (medium when unread, normal when read — via conditional `font-medium` / `font-normal`)
  - Body (if non-null): `<p className="text-xs text-muted-foreground truncate mt-0.5">`
  - Category badge: `<Badge variant="outline" className="text-[10px] h-4 mt-1">` — lowercase category string
- Timestamp: `<time className="text-xs text-muted-foreground flex-shrink-0 ml-2">` — relative format ("2m ago", "1h ago", "yesterday") via consumer-supplied formatter or `Intl.RelativeTimeFormat`

**Interaction:** Entire row is a `<button>` (or `role="button"` div) — click marks the item read (optimistic) and calls `onNavigate(href)` if `href` is non-null. Focus ring: `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 rounded-sm`.

**Row background:** Unread items use `bg-muted/30` background. Read items use transparent (default card bg). Transition: `transition-colors`.

### 5b. WebhookHealthBadge

**Derivation logic (from D-15 — locked):**
```
if (!endpoint.enabled)                                                   → 'Disabled'
if (endpoint.failureCount > 0 ||
    (endpoint.lastFailureAt && endpoint.lastSuccessAt &&
     endpoint.lastFailureAt > endpoint.lastSuccessAt))                   → 'Failing'
else                                                                      → 'Healthy'
```

**Visual:**

| Status | Tailwind | Badge variant | Icon |
|--------|----------|---------------|------|
| Healthy | `text-primary bg-primary/10 border-primary/20` | `variant="outline"` + className override | `CheckCircle2 h-3 w-3` |
| Failing | `text-destructive bg-destructive/10 border-destructive/20` | `variant="outline"` + className override | `AlertCircle h-3 w-3` |
| Disabled | `text-muted-foreground` | `variant="secondary"` | `CircleOff h-3 w-3` |

Badge size: `text-xs h-5` — use `<Badge>` with `className` override.

## Tag Input Specification (Event Types Field)

Phase 3 introduces one interactive input pattern not covered by Phase-1/2 primitives: a chip/tag input for free-form glob event-type patterns.

**Implementation:** Build as a net-new `EventTypesInput` component in `components/webhooks/`. Do NOT install a third-party tag input library — the pattern is simple enough to implement with a controlled `<Input>` + `useState`.

**Behavior:**
- Renders existing tags as `<Badge variant="outline" className="gap-1">` with an `<X className="h-3 w-3 cursor-pointer" aria-label="Remove {tag}">` icon
- `<Input>` with `placeholder="Type and press Enter or comma"` appends a tag on Enter keydown or comma keydown (trim whitespace, skip empty, skip duplicates)
- Tag validation: 1–100 chars per tag; max 50 tags total — show `<p className="text-xs text-destructive">` inline error when exceeded
- Suggested patterns shown as `<Button variant="ghost" size="sm">` chips below the input: `dataset.*`, `agent.run.completed`, `pipeline.run.completed`, `webhook.*` — clicking appends to the tag list

**Accessibility:** The input has `aria-label="Event types"`. Each remove button has `aria-label="Remove {tagValue}"`. The container has `role="group"` and `aria-labelledby` pointing to the field label.

## Accessibility Contract

All Phase 3 surfaces must satisfy CORE-05 baseline inherited from Phase 2.

| Requirement | Implementation |
|-------------|----------------|
| Visible focus rings | All interactive elements use `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2` — provided by Phase-2 Button/Switch/Input/Badge primitives out of the box |
| Icon-only buttons carry aria-label | NotificationBell: `aria-label="Notifications"`. Copy button in SecretReveal: `aria-label="Copy signing secret to clipboard"`. Tag remove buttons: `aria-label="Remove {tag}"`. Webhook enable toggle: `aria-label="Enable webhook"`. |
| Live region for unread count | `<span aria-live="polite" aria-atomic="true">` wrapping the bell badge count. Screen readers announce "9 notifications" on change. |
| Dialog focus-trap | Radix Dialog (`<Dialog>`) traps focus automatically. SecretReveal modal is not dismissible via outside-click (`onInteractOutside` preventDefault). |
| ConfirmDialog focus-trap | Radix AlertDialog (used inside `<ConfirmDialog>`) traps focus. Default focus lands on the cancel button (safe default). |
| Switch labeling | All preference Switches use `id` + `<Label htmlFor>` pairing OR `aria-label` if no visible Label. |
| Loading state announcement | Loading state components (skeletons) do NOT need aria-live — they are replaced by real content; the page title/heading remains visible during load. |
| Keyboard operability | Popover opens/closes with Enter/Space/Escape. Tag input: Enter/comma adds tag, Backspace on empty input removes last tag. |
