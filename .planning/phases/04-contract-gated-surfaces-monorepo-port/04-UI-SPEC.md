## CSS Import Order Contract (xyflow — LOCKED in Phase 4)

This is the canonical consumer CSS order, locked by D-09 and verified by the PORT-01 Vite app:

```css
/* apps/web/src/index.css  OR  examples/farsight-ui-consumer/src/index.css */
@import "tailwindcss";
@import "@farsight/ui/theme.css";          /* tokens + @source */
@import "@xyflow/react/dist/style.css";    /* MUST come AFTER tailwindcss reset */
```

**Why this order matters:** Tailwind v4's reset sets `overflow: hidden` on some selectors.
`@xyflow/react/dist/style.css` must come after so xyflow's edge/viewport styles win. Getting
this wrong makes edges invisible (`.react-flow__edges` container is clobbered). The canvas-kit
components do NOT import `@xyflow/react/dist/style.css` directly — the consumer's global CSS
is the only correct location.

**`@source` for the Vite consumer (R-05):** The `theme.css` `@source "../../src"` path is valid
from the source tree but resolves to a non-existent path after `tsdown` build. The `examples/`
Vite consumer MUST add an explicit `@source` directive:
```css
/* Add after @import "@farsight/ui/theme.css": */
@source "../../../packages/ui/src";  /* workspace-relative in monorepo dev */
/* For published npm consumers: @source "./node_modules/@farsight/ui/dist" */
```

## Typography

Reuses the Phase-1/2/3 type scale exactly. No new sizes introduced in Phase 4.

| Role | Tailwind | Size | Weight | Line Height | Usage in Phase 4 |
|------|----------|------|--------|-------------|------------------|
| Body | `text-sm` | 14px | 400 (normal) | 1.5 | Dataset descriptions, record values, chat message text, workflow name in list |
| Label / Meta | `text-xs` | 12px | 400 (normal) | 1.4 | Dataset kind badge, status badge, record count, node type label, run status, message timestamp |
| Heading | `text-base font-medium` | 16px | 500 (medium) | 1.25 | Dataset detail section headings, canvas inspector panel heading, chat agent name |
| Display | `text-lg font-medium` | 18px | 500 (medium) | 1.2 | DatasetList page heading, WorkflowList page heading, AgentChatView heading |

**Weight contract (inherited from Phase 3):** Two weights only.
- Regular (400): all body copy, meta, timestamps, record values, helper text, URL/path strings.
- Medium (500): headings, panel titles, node labels, action labels, column headers.

No `font-bold` (700) or `font-semibold` (600) in Phase 4 surfaces.

**Canvas node label:** `text-xs font-medium` (12px / 500) — nodes are compact; medium weight
distinguishes the node name from its type annotation without needing size escalation.

**RAG search result score:** Render similarity score as `text-xs text-muted-foreground` with
`font-mono` — a percentage or 0–1 decimal. No special weight treatment.

**Agent message text parts:** `text-sm` (14px) at weight 400, line-height 1.5 — same as body
copy. Assistant responses may be long; 1.5 line-height is required for readability. Render as
`<p>` elements (one per `text` part), not `<pre>`.

## Surface Specifications

### 1. DatasetList

**Form factor:** Full-width page with DataTable, toolbar above.

**Primary visual anchor:** The Name column (`text-sm font-medium`) is the first legible element per row and the row-click target.

**Anatomy:**
- Page wrapper: `<div className="p-8">` (xl spacing)
- Heading row: `<div className="flex items-center justify-between mb-6">` — `<h2 className="text-lg font-medium">Datasets</h2>` — no CTA in toolbar (create dataset is out of scope per REQUIREMENTS.md)

| Column | Key | Render |
|--------|-----|--------|

### 3. DatasetSearch (RAG search surface)

**Form factor:** Search input + result list, rendered inside the dataset detail search tab.

**Anatomy:**
- Search form: `<form className="flex gap-2" onSubmit={handleSearch}>`
  - `<Input type="search" placeholder="Search dataset..." className="flex-1" />` with `<Label className="sr-only">Search query</Label>`
  - `<Button type="submit" disabled={isPending}>` — "Search dataset" (idle) / "Searching..." (pending)
- Backend indicator: `<p className="text-xs text-muted-foreground mt-2">` — shows which backend is active when a result is available: "Vector search", "AI search", or "Keyword search" per color contract above
- Result list: `<div className="mt-4 space-y-2">` — `{results.matches.map((match) => <SearchResultItem key={...} match={match} backend={backend} />)}`
- `indexingPending` notice (vectorize only): `<div className="flex gap-2 rounded-md bg-[var(--color-chart-4)]/10 px-4 py-2 text-xs text-[var(--color-chart-4)] mb-2">` — `<AlertTriangle className="h-3.5 w-3.5 flex-shrink-0 mt-0.5" />Results may be incomplete while indexing is in progress.`
- Loading (search in flight): 3 `<Skeleton className="h-16 w-full rounded-md" />` rows
- Error: `<ErrorState title="Search failed" description="Try a different query or check your connection." onRetry={handleSearch} />`

**`SearchResultItem` — discriminated by `backend`:**

All three branches share a wrapper: `<div className="rounded-md border bg-card p-4 space-y-1">`.

| `backend` | Match shape | Primary text | Secondary text | Score |
|-----------|-------------|-------------|----------------|-------|
| `'vectorize'` | `{ id, score, metadata? }` | `metadata` keys rendered as `<dl>` pairs, or `id` if no metadata | — | `<Progress value={score * 100} className="h-1 mt-1" />` + `text-xs text-muted-foreground font-mono` score value |
| `'ai_search'` | `{ key, score, text? }` | `text` (if present) as `<p className="text-sm">`, else `key` as `<code className="text-xs font-mono">` | `key` rendered as `<code className="text-xs font-mono text-muted-foreground">` | `text-xs text-muted-foreground font-mono` score value |
| `'none'` | `{ recordId, title?, snippet? }` | `title` or `recordId` as `text-sm font-medium` | `snippet` as `<p className="text-xs text-muted-foreground line-clamp-2">` | No score |

**Empty state (no results):**
```
<EmptyState
  title="No results"
  description="Try a different query or broaden your search."
  icon={SearchX}
/>
```

**Backend `'none'` with no search performed yet (initial state before user submits):**
```
<EmptyState
  title="Search this dataset"
  description="Enter a query above to find records."
  icon={Search}
/>
```

### 5. WorkflowCanvas (Pipeline canvas surface)

**Form factor:** Full-viewport canvas with floating inspector panel and toolbar.

**Primary visual anchor:** The canvas area + the top-bar "Run pipeline" / "Save pipeline" CTA pair.

**Overall layout:**
```
[canvas toolbar — top bar: name + active badge + Run pipeline/Save pipeline buttons]
[xyflow canvas — fills remaining height]
  [canvas palette — left side, absolute positioned]
  [canvas inspector — right side, slides in when node selected]
  [canvas controls — bottom right: zoom+/zoom-/fit, aria-labels via Tooltip]
```

**Canvas toolbar:**
- `<div className="flex items-center justify-between border-b bg-card px-4 py-2">`

**Canvas area:**
- `<div className="relative flex-1 h-full">`
- `<CanvasFlow nodeTypes={nodeTypes} edgeTypes={edgeTypes} nodes={nodes} edges={edges} onNodesChange={onNodesChange} onEdgesChange={onEdgesChange} onConnect={onConnect} onNodeClick={onNodeClick} fitView>`
  - `<CanvasBackground />` — dots, `var(--color-border)`
  - `<CanvasControls />` — zoom in / zoom out / fit view, each button wrapped in `<Tooltip>` with aria-label
  - `<CanvasMiniMap />` — optional; controlled by consumer `showMiniMap` prop (default true)
  - `<CanvasPalette>` — fixed 3 items: Source, Transform, Sink; draggable onto canvas
  - `<CanvasInspector>` — slides in when `selectedNode !== null`; shows node parameters form

**Loading state:** Full canvas area shows `<DetailSkeleton />` (3 stacked skeleton bars) until
`useWorkflow(wfSlug)` resolves. The canvas does not mount until data is available.

**Error:** `<ErrorState title="Could not load pipeline" onRetry={refetch} />` in place of canvas.

**Canvas inspector panel (`<CanvasInspector>`):**
- Position: absolute right-0 top-0, `w-80 h-full bg-card border-l shadow-sm` with transition
- Header: `<div className="flex items-center justify-between p-4 border-b">` — node name `<h3 className="text-base font-medium">` + `<Button variant="ghost" size="icon" aria-label="Close inspector" onClick={deselectNode}><X className="h-4 w-4" /></Button>`
- Node type label: `<code className="text-xs font-mono text-muted-foreground px-4">` — the Farsight NodeId string
- Parameters form: `<div className="p-4 space-y-4 overflow-y-auto">` — one `<div>` per parameter key with `<Label>` + `<Input>` or `<Textarea>`. Parameters are `Record<string, unknown>` — render all string/number values as `<Input type="text">`, boolean values as `<Switch>`.
- Save parameters: `<Button className="mx-4 mb-4 w-[calc(100%-2rem)]" onClick={handleSaveParams}>Apply changes</Button>`

**Canvas node inner padding:** `p-2` (8px) for source/transform/sink node bodies — keeps nodes compact without crowding the label.

**Keyboard / a11y for canvas:**
- Canvas zoom buttons: `aria-label="Zoom in"`, `aria-label="Zoom out"`, `aria-label="Fit view"` (via Tooltip)
- Canvas keyboard-pan: xyflow provides arrow-key pan natively — document in consumer README but do not re-implement
- Node selection: xyflow handles focus on node click; note in README that xyflow's built-in a11y for canvas nodes is limited (no ARIA role on flow nodes in xyflow v12) — acceptable given the WCAG exemption for complex visualizations with an accessible alternative
- Inspector close button: keyboard-focusable, `aria-label="Close inspector"`
- Palette drag-to-add nodes: each palette item is a `<button>` that adds a node to the canvas center on Enter/Space (as an alternative to drag-and-drop)
- `aria-label="Pipeline canvas"` on the ReactFlow wrapper div

### 7. AgentChatView

**Form factor:** Full-height chat surface. Consumer provides `agentDefinitionId` as a prop —
no agent enumeration or selection UI in this surface.

**Primary visual anchor:** The message list (most recent message) + the composer Send control.

**Anatomy:**
```
[chat header: agent name + agentDefinitionId]
[message list: ScrollArea, fills available height, newest at bottom]
[composer: textarea + send button]
```

- Chat wrapper: `<div className="flex flex-col h-full bg-background">`
- Header: `<div className="flex items-center gap-2 border-b bg-card px-4 py-2 flex-shrink-0">` — `<Bot className="h-5 w-5 text-primary" />` + `<h2 className="text-base font-medium">{agentLabel ?? agentDefinitionId}</h2>` + status polling indicator (see below)
- Message list: `<ScrollArea className="flex-1" ref={scrollRef}>` — auto-scrolls to bottom on new messages
- Composer: `<div className="border-t bg-card px-4 py-2 flex-shrink-0">`
  - `<form className="flex gap-2 items-end" onSubmit={handleSubmit}>`
  - `<Textarea placeholder="Message the agent..." className="flex-1 min-h-[80px] resize-none" value={message} onChange={setMessage} onKeyDown={handleKeyDown} aria-label="Message input" />`
  - `<Button type="submit" size="icon" disabled={!message.trim() || isPending} aria-label="Send message" className="flex-shrink-0 self-end"><Send className="h-4 w-4" /></Button>`
  - `Ctrl+Enter` / `⌘+Enter` submits (do NOT submit on bare Enter — allow newlines in message)

**Polling status indicator:**
- Shows a pulsing `<span className="h-2 w-2 rounded-full bg-primary animate-pulse" aria-hidden="true" />` while `isFetching` is true (background refetch on 2s interval)
- `<span className="sr-only" aria-live="polite">` — announces "New messages" when message count increases

**Loading state (initial messages fetch):**
- Show 3 `<Skeleton className="h-12 rounded-xl" />` rows (2 right-aligned for user, 1 left-aligned for assistant)

**Empty state (no messages yet):**
```
<EmptyState
  title="Start a conversation"
  description="Send a message to begin."
  icon={MessageCircle}
/>
```

**Error state:**
```
<ErrorState title="Could not load messages" description="Check your connection and try again." onRetry={refetch} />
```

### 8. AgentMessage (single message row)

**Anatomy per `role`:**

```
user:      [spacer flex-1] [bubble: user bg] [avatar initial]
assistant: [avatar icon]   [bubble: muted bg] [spacer flex-1]
system:    [full-width centered italic muted text]
```

- Message wrapper: `<div className={cn("flex items-end gap-2 mb-2", role === 'user' ? "flex-row-reverse" : "flex-row")}>`
- Avatar (user): `<div className="h-7 w-7 rounded-full bg-primary flex items-center justify-center text-xs text-primary-foreground font-medium flex-shrink-0">` — first letter of userId or "U"
- Avatar (assistant): `<div className="h-7 w-7 rounded-full bg-muted flex items-center justify-center flex-shrink-0"><Bot className="h-4 w-4 text-muted-foreground" /></div>`
- Bubble: `<div className={cn("max-w-[75%] rounded-2xl px-4 py-2", role === 'user' ? "bg-primary text-primary-foreground rounded-br-sm" : "bg-muted text-foreground rounded-bl-sm")}>`
- Parts renderer: render `parts[]` — for `type: 'text'` render `<p className="text-sm leading-relaxed whitespace-pre-wrap">`. For unknown part types, render nothing (pass-through opacity-0 placeholder). Never `dangerouslySetInnerHTML`.
- Timestamp: `<time className="text-xs text-muted-foreground flex-shrink-0 mb-1">` — relative format ("just now", "2m ago")

**System messages:** `<p className="text-xs text-muted-foreground italic text-center my-2 px-4">` — full-width, no bubble, no avatar.

**Accessibility:**
- Message list has `role="log"` and `aria-label="Chat messages"` and `aria-live="polite"` — announces new messages without interrupting user mid-type
- Each message `<article>` has `aria-label="{role} message"` for screen reader disambiguation
- The composer `<Textarea>` has `aria-label="Message input"`
- Send button has `aria-label="Send message"`

## Accessibility Contract

All Phase 4 surfaces inherit and extend the Phase-2 CORE-05 baseline.

| Requirement | Implementation |
|-------------|----------------|
| Visible focus rings | All interactive elements use `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2` via Phase-2 primitives |
| Icon-only buttons carry aria-label | Canvas controls: zoom-in, zoom-out, fit-view (via Tooltip). Back button in canvas toolbar. Inspector close button. Agent send button. Workflow list open-canvas button. |
| aria-live for chat messages | `role="log" aria-live="polite"` on the AgentChatView ScrollArea. `<span className="sr-only" aria-live="polite">` announces "New messages" on polling arrival. |
| aria-live for run status | WorkflowRunView status text has `aria-live="polite"` to announce status changes without user action |
| Canvas a11y note | xyflow v12 does not assign ARIA roles to individual flow nodes — this is an accepted limitation of complex visualization components (WCAG 1.1.1 exception for "pure decoration" when complex alt is impractical). Document in PORT-02 consumer README. |
| Keyboard-pan for canvas | xyflow provides arrow-key viewport pan natively (no implementation needed). Document in README. |
| Palette drag alternative | Each palette item is a `<button>` — pressing Enter/Space appends the node at the canvas center. |
| DataTable keyboard | Phase-2 DataTable/DataGrid handles row focus + arrow-key navigation. No new work needed. |
| Search input | `<Label className="sr-only">Search query</Label>` + associated `<Input>` ensures screen reader label without visible label (design uses placeholder only). |
| Textarea submit shortcut | `Ctrl+Enter` / `⌘+Enter` submits chat form. Label documents this: `aria-describedby` pointing to `<span className="sr-only">Press Ctrl+Enter to send</span>`. |
| ConfirmDialog focus-trap | Radix AlertDialog (inside `<ConfirmDialog>`) traps focus. Default focus lands on cancel button. |
