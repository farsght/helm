use-agents hook (from 04-PATTERNS.md §use-agents.ts):
```typescript
export const agentKeys = {
  messages: (agentDefinitionId: string, chatId?: string) =>
    ["agents", agentDefinitionId, chatId ?? "default", "messages"] as const,
}

// Note: agents are NOT project-scoped in the contract — no orgSlug/projectSlug in key
// agentDefinitionId is consumer-provided (like a static registry ID)
export function useAgentMessagesQueryOptions(agentDefinitionId: string, chatId?: string) {
  const { client } = useFarsightContext()
  return queryOptions({
    queryKey: agentKeys.messages(agentDefinitionId, chatId),
    queryFn: () => (client.agents.messages as AnyFn)({ params: { agentDefinitionId }, query: chatId ? { chatId } : undefined }),
    refetchInterval: 2_000,              // 2s poll for chat UX
    refetchIntervalInBackground: false,  // pauses when tab hidden
    staleTime: 1_000,
    enabled: !!agentDefinitionId,
  })
}
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-T1 | Tampering | AgentMessage parts[] rendering — XSS via agent content | mitigate | All message parts rendered as React text nodes via {p.text} — never dangerouslySetInnerHTML. Unknown part types silently skipped. React's JSX escaping prevents injection. This is the primary XSS surface in this plan. |
| T-04-05-T2 | Tampering | AgentChatView submit message input | accept | Message string sent as-is to the backend; Farsight API enforces 1–8000 char limit in the contract schema. Client-side input is not executable — only the backend processes it. No injection risk from the client perspective. |
| T-04-05-ID | Information Disclosure | agentKeys not namespaced by project | accept | Agents contract has no project-scope (no projectSlug in agentsRoutes). The key is scoped to agentDefinitionId — correct for the Farsight model (static registry entries). No cross-tenant data risk at the agent-key level; the SDK's Bearer token enforces org isolation at the network layer. |
| T-04-05-D | Denial of Service | 2s polling refetchInterval for messages | accept | refetchIntervalInBackground: false pauses polling when tab is hidden. 2s is appropriate for chat UX. The consumer can pass interval={false} to disable polling. |
</threat_model>
